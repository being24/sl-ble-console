# SL 指導コンソール

指導用ファーム（`slider_sensors` の `coach/`、台の名前 `COACH1`・`COACH2`）に BLE でつなぎ、指標をリアルタイムのグラフにするページ。
記録用の操作ページ（一つ上の `index.html`）とは別のページで、台は別のファームです。

https://being24.github.io/sl-ble-console/coach/

## 使い方

1. 台に指導用ファームを書き込む（`slider_sensors` の `docs/coach_manual.md`）。
2. Web Bluetooth に対応したブラウザ（Android・PC の Chrome、iPad は Bluefy）で上の URL を開く。
3. 「接続」で `COACH` から始まる台を選ぶ。
4. 台を静止させたまま「0点合わせ」（足圧の0点を取る）。
5. 氷の変化を見たいときは、「氷の基準を取る」を押して滑る（滑走中の約8窓、約4秒ぶんの平均を基準にする）。
6. 台の SD に残したいときは、滑る前に「SDに20秒記録」を押す。20秒で自動で止まり、途中なら「記録停止」。記録中は、右上のバッジが「SD に記録中」になる。残るのは、その20秒の指標と LFCC（1回の記録が1ファイル。生のセンサ値は残らない）。滑走の検知は、画面の表示だけに使い、記録は、ボタンを押したときだけ始まる

7. 動画と一緒に見返したいときは、「カメラ」を押して（背面カメラ）、「動画を撮る」で撮影を始め、「撮影停止」で止める。止めると、その動画の再生に切り替わり、グラフと数値が動画の再生位置に合う（直近20秒）。「ライブに戻る」でカメラ映像に戻る。「動画とCSVを保存」で、動画と、同じ時刻軸（動画の先頭からの ms、`video_ms`）の CSV を、同じ名前で保存する（2ファイルを同時にダウンロードするので、初回は、ブラウザが複数ダウンロードの許可を聞く）。撮影の開始が数百ms遅れることがあり、その分は、動画とグラフにずれる
8. 「動画とSDを連動」（既定でオン）のとき、「SDに20秒記録」と「動画を撮る」は、どちらを押しても両方が始まり、どちらかが止まれば（動画の停止、「記録停止」、SD の20秒の自動停止、SD が始まらなかったとき）両方が止まる。連動で撮った動画の保存名には、台の SD のファイル名が入る。始めるときに、グラフは消える
9. グラフをタップすると全画面になる（もう一度タップか Esc で戻る）。各グラフの下で、縦軸の下限・上限を数字で決められる（空欄は自動）。「テーマ」ボタンで、自動・ライト・ダークを切り替える（選んだ値は覚える）。画面の上に、台の SD の最新のファイル名と、次のファイル名（予想）が出る

台なしで見た目だけ確かめるには、「デモ」ボタン、または `?demo=1` を付けて開く。ハブ（`hub-v0.2.0` 以降）が台につないでいる間は、このページはつながらない（BLE の接続が1本のため）。

## 画面の指標

| 表示 | 中身 | 注意 |
|---|---|---|
| 左右の荷重バランス | (右−左)/(右+左) | 足圧の位置は台ごと・日ごとに違い、出力も小さいので参考値 |
| 横ぶれ | 横の加速度 X の5Hz以下の0.5秒窓 RMS [g] | 点線は 2026-10-14 の Used の中央値（経験者 0.05 g、初心者 0.14 g）。**良し悪しの判定はしない**。MOCAP での照合は未実施 |
| 向きの回転 | ジャイロ Z の5Hz以下の0.5秒窓 RMS [dps] | |
| 総荷重 | 足圧センサの出力の合計（0点合わせ後）[V] | 頭打ちのときはバッジで知らせる |
| 氷の基準からの距離（参考） | 滑走中の約0.5秒ごとの LFCC（IIS3DWB）が、基準の平均からどれだけ離れたか | 氷の種類（used / fine / rough_fine）は判定しない。人をまたぐ識別の精度が弱いため |

## ファイル

- `coach.js` — パケットの読み取り、基準からの距離（Web Bluetooth に依存しない）。`node --test` でテスト（`test/protocol.test.js`）
- `chart.js` — 依存なしの折れ線グラフ（canvas）
- `app.js` — 接続、画面の更新、CSV 保存、動画の撮影と再生、動画とSDの連動、デモ
- `index.html` — 画面

パケットの形式は `slider_sensors` の `docs/coach_protocol.md`。ファームの `coach/tests_host/test_coach_proto.c` と
`test/protocol.test.js` は、同じバイト列を期待値にしている。

## 未確認

確認できているのは、デモ、バイト列のテスト（node）、と、接続時にページが送る `T` が台に届くこと（台側のデバッガの値）まで。
次は、実機で確かめていない: 画面のボタン（`S`・`P`・「0点合わせ」）、動画の撮影と再生、動画と SD の連動、グラフの拡大・縦軸の上下限・テーマの切り替え、SD の次のファイル名の表示。動画の機能は、ブラウザでも動かしていない（ブラウザ操作ツールが接続できなかったため）。
